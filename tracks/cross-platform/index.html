跨平台

CROSS-PLATFORM · Flutter / React Native

一套代码多端运行，用开发效率换部分原生上限。Flutter 自绘引擎追求一致与性能，RN 复用 Web 技能与原生组件。选型核心是团队技术栈与性能/一致性要求。

两条路线

ROUTES
🦋

Flutter

规划中

Dart + 自绘引擎（Skia/Impeller）。

  • 基础：Dart、Widget 树、状态管理
  • 框架：Flutter / Riverpod / Bloc
  • 架构：多端统一 UI、平台通道、性能优化
多端统一品牌 UI、独立 App 团队
📱

React Native

规划中

JS/TS + 原生组件桥接。

  • 基础：React 思想、JSX、新架构
  • 框架：RN / Expo / 导航与状态
  • 架构：原生模块、热更新、与 Web 复用
已有 React 团队、快速迭代、内容型 App

跨平台选型决策

WHEN TO USE WHAT
场景约束倾向关键理由
已有 React/JS 团队React Native技能与组件复用、生态成熟、Expo 提速
多端 UI 高度一致、品牌化Flutter自绘引擎一致性好、性能接近原生
重度原生能力 / 极致性能原生（见移动端）跨平台有桥接/上限成本
权衡提醒跨平台不是「免费午餐」：原生能力要桥接、极致性能有上限、包体与启动需优化。先确认场景能接受这些代价，再选跨平台——把这个权衡讲给 AI，它才不会盲目套用。
