AI 应用开发

AI APPLICATION · 把模型能力变成产品

这是全栈指南的「AI 时代」核心增量：不是训练大模型，而是把现成模型能力工程化成可靠产品。懂接入、增强、编排、评估四层的原理与边界，才能选对方案、指挥 AI 搭出可控的 AI 应用。

四层能力

FOUR LAYERS
🔌

LLM 接入

规划中

把模型接进来。

  • 原理：API/流式、Token 计费、上下文窗口
  • 工程：多模型路由、限流、超时降级
  • 选型：直连 vs 网关、自托管 vs 云
对话产品、AI 网关、模型代理
📚

RAG 检索增强

规划中

让模型用上私有知识。

  • 原理：嵌入、向量检索、重排、生成
  • 工程：分块策略、向量库、引用溯源
  • 选型：RAG vs 微调 vs 长上下文
企业知识库、文档问答、客服
🧩

Agent 编排

规划中

让模型多步做事。

  • 原理：工具调用、ReAct、规划与反思
  • 工程：工作流、状态、可控性与护栏
  • 选型：单 Agent vs 多 Agent vs 固定流程
自动化任务、智能助手、复杂流程
📊

评估与可观测

规划中

让产品可靠上线。

  • 原理：质量评估、幻觉治理、回归
  • 工程：链路追踪、成本监控、A/B
  • 选型：离线评估 vs 在线监控
AI 产品上线、质量保障、持续优化

AI 应用选型决策

WHEN TO USE WHAT
场景约束倾向关键理由
私有知识问答、知识常更新RAG可更新、成本低、可溯源，优于微调
固定风格/格式、知识稳定微调风格内化、推理省 Token
多步任务、要调工具Agent工具调用 + 规划，但需护栏控风险
流程确定、要稳定可控固定工作流比自由 Agent 更可预测、易验收
多厂商、要控成本与可用性AI 网关统一路由/限流/计量/降级
核心心法AI 应用最大的坑是「不可控」。先想清楚要确定性还是要灵活性：能用固定流程就别上自由 Agent，能用 RAG 就别急着微调。把边界与护栏写进给 AI 的指令，产品才稳。
