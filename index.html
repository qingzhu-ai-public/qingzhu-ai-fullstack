AI 时代的全栈学习指南

不一定要亲手写每一行，
但要知道什么场景该用什么架构

这是一份「决策导向」的全栈指南。我们学基础原理、框架与架构的适用边界——搞清楚每种技术解决什么问题、什么场景该选它，然后用清晰的指令把实现交给 AI。懂原理、会选型、能指挥 AI，就是 AI 时代的全栈能力。

后端 · Java / Python / Go / Node.js前端 · Vue / React移动端 · Android / iOS / 鸿蒙跨平台 · Flutter / RNAI 应用开发

怎么用这份指南

HOW IT WORKS

每个方向都按同一条主线组织：先懂原理，再会选型，最后交给 AI。不追求背诵 API，追求「遇到场景能做出正确判断」。

1

懂原理

每个框架/架构解决什么问题、核心机制是什么、边界在哪。知道「为什么」，才不会被 AI 的错误答案带偏。

2

会选型

按场景选技术：团队规模、性能要求、生态、交付速度。指南给出「什么场景用什么」的决策依据，而非唯一标准答案。

3

交给 AI

把选好的架构和约束写成清晰指令，让 AI 生成实现。你负责判断对错、验收质量——这正是懂原理的价值。

架构选型心法

DECISION FIRST

没有「最好的技术」，只有「最适合场景的技术」。下面是几个典型判断，体会选型思路——这正是你要学会、然后告诉 AI 的部分。

场景倾向选型为什么
大型企业业务系统、长期维护Java + Spring生态成熟、强类型、人才多、可维护性强
AI 服务 / 数据管道 / 快速原型Python + FastAPIAI 库最全、开发快、与模型生态无缝
高并发微服务 / 云原生中间件Go并发模型轻、部署简单、资源占用低
全栈 JS 团队 / 实时 BFFNode.js前后端同语言、IO 密集高效、迭代快
已有 React 团队做 AppReact Native复用技能与组件、生态成熟
多端统一品牌 UI、独立 AppFlutter自绘引擎一致性好、性能接近原生
私有知识问答RAG（而非微调）知识可更新、成本低、可溯源
核心心法选型是「权衡」不是「站队」。先问场景约束（团队、性能、生态、交付速度），再选技术，最后把架构与约束写成指令交给 AI 实现。你保留判断与验收的权力。
